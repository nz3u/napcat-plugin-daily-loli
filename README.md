# NapCat 每日 LC0 图片插件

为 NapCat 提供每日 LC0 图片定时推送和群内关键词查询。基于 [NapCat 插件模板](https://github.com/NapNeko/napcat-plugin-template) 开发，处理上游标签为 `LC0` 或 `LC YJ` 的卡片。

> 本文的消息示例均使用占位符，不包含真实接口响应、作者昵称、角色信息、作品链接、推荐者或 QQ 群号。功能参数和公共接口地址属于项目说明，不是用户数据。

## 功能

- 每天北京时间（UTC+8）**07:21** 开始获取当日内容，推送到配置的群。
- 在允许的群中发送纯文本 **今日图片** 查询当前内容；去除首尾空白后精确匹配，不响应私聊或含引用、@、图片的混合消息。
- 插件总开关、定时推送开关、关键词开关相互独立；两种功能分别配置群白名单，**空列表不发送、不响应**。
- 支持详细版和简略版消息；可用信息包括图片、日期、评级、画师、角色、作品来源、备注和推荐者。
- 上游提供公告时，会作为一行随当日内容一起发布。
- 支持主备接口回退、请求超时、5 分钟缓存、并发请求合并及按群冷却。
- 定时失败每分钟重试，连续失败达到上限后停止当天重试并按需提醒，等待人工排查。
- 逐群保存成功记录；重启后补发当天尚未成功的群。

## 安装

要求 NapCat **4.14.0 或更高版本**，建议使用最新稳定版。开发环境建议 Node.js 20 或更高版本。

1. 解压发布包 `napcat-plugin-daily-loli.zip`。
2. 将插件放入 NapCat 的 `plugins/napcat-plugin-daily-loli/` 目录，确保该目录直接包含 `package.json` 和 `index.mjs`，不要嵌套额外目录。
3. 在 NapCat WebUI 插件管理中加载并启用 **每日 LC0 图片**。
4. 打开插件原生配置面板，分别填写需要使用的群白名单并保存。机器人必须已加入目标群且具有发言权限。

开发构建后，也可将 `dist/` 的内容复制到插件目录。安装包没有第三方运行时依赖，无需在该目录安装依赖。

插件使用 NapCat 原生配置面板，不提供独立仪表盘或无鉴权配置 API。支持 `napcat.icon` 字段的版本会显示插件图标；旧版本忽略图标不影响使用。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 插件总开关 |
| `scheduledEnabled` | `true` | 每日定时推送开关 |
| `scheduledGroups` | `""` | 定时推送群白名单，空列表不推送 |
| `keywordEnabled` | `true` | “今日图片”关键词开关 |
| `keywordGroups` | `""` | 关键词触发群白名单，空列表不响应 |
| `compactMode` | `false` | 简略版，只展示日期、评级和角色，仍发送图片 |
| `cooldownSeconds` | `60` | 单群关键词冷却，范围 0–3600 秒 |
| `requestTimeoutSeconds` | `15` | 单个接口超时，范围 3–60 秒 |
| `maxRetryAttempts` | `10` | 定时推送最大连续失败次数，达到后当天停止重试，`0` 表示不限制 |
| `failureAlertEnabled` | `true` | 停止重试时向当天尚未成功的定时群发送一条提醒 |

群号列表支持逗号、空格或换行分隔，只能在本地配置中填写真实目标群号。以下示例有意留空，复制后不会向任何群发送消息：

```json
{
  "enabled": true,
  "scheduledEnabled": true,
  "scheduledGroups": "",
  "keywordEnabled": true,
  "keywordGroups": "",
  "compactMode": false,
  "cooldownSeconds": 60,
  "requestTimeoutSeconds": 15,
  "maxRetryAttempts": 10,
  "failureAlertEnabled": true
}
```

保存后配置即时生效。关闭开关不会撤回已提交给 QQ 的消息；关键词查询不修改定时推送成功记录。简略版设置对两种发送方式都有效。

### 冷却与并发

- 冷却按群独立计算，从接受触发消息、开始请求前计时，覆盖获取和发送过程。
- 冷却期间的触发会被静默忽略，不回复、不排队；同群并发触发只处理一条。
- `cooldownSeconds: 0` 关闭正常冷却，但获取或发送失败后仍保留 10 秒兜底冷却，避免故障时刷屏。
- 重载时旧实例会停用；有明确消息 ID 的重复事件会被去重。

## 消息格式

**以下内容仅表示格式，尖括号内均为占位符，不是可直接发送的真实数据。** 可选字段由接口是否提供决定，不一定全部出现。

详细版（默认）：

```text
公告：<公告内容>
今日图片 · <内容日期> · LC0
画师：<画师名称>
角色：<角色名称>（#<角色ID>）
作品来源：<作品来源URL>
备注：<备注内容>
推荐：<推荐者昵称>
[图片]
```

简略版：

```text
公告：<公告内容>
今日图片 · <内容日期> · LC0
角色：<角色名称>（#<角色ID>）
[图片]
```

角色缺少 ID 时只展示名字。两种版本都不输出画师主页或单独的角色链接行。简略版省略画师、作品来源、备注和推荐者。

公告行由上游提供时出现，位于最前面，每天只发一次，不会随每张卡片重复。

## 时间与重试

- 内容日以北京时间 **07:21** 为边界，此前使用前一内容日，不按服务器本地时区或零点切换。
- 在线时每 20 秒检查一次。网络请求和 QQ 发送可能产生额外延迟，不保证秒级准点。
- 07:21 后加载插件、开启定时推送或新增目标群，会尝试补发当天尚未成功的群；此前不自动补发昨日。
- 上游未更新、无可用 LC0 卡片或发送失败时，定时任务每分钟重试，不使用昨日内容或其他评级替代。
- 连续失败达到 `maxRetryAttempts` 次后当天停止重试，并可按开关向尚未成功的定时群发送一条提醒；只要有一个群成功，失败计数即归零。
- 停止重试后不会自动恢复：排查接口、网络、群白名单与机器人发言权限后，重新保存配置或重载插件即可恢复重试。换日也会重新开始计数。
- 成功记录保存在 NapCat 分配的插件数据目录中，文件名为 `delivery-history.json`。同一日期同一群成功后不会因开关切换再次定时推送。
- 每个群的全部卡片作为一条消息提交。网络故障下可能出现服务端已接收、客户端却超时的情况，因此不能保证绝对的仅发送一次。

## 数据来源与安全边界

插件使用以下公共 GET 接口，无需登录、Cookie 或 App Secret：

- 主接口：<https://loliconey.tsuki.ga/api/v1/daily?badge=LC0>
- 备用接口：<https://lc-coney.deno.dev/api/v1/daily?badge=LC0>

备用部署可能不可用，配置了回退不代表上游始终可用。接口响应结构为 `{ "date": "<内容日期>", "cards": [] }`，此处仅描述结构，不展示真实响应。

插件检查内容日期，只接受标签为 `LC0` 或 `LC YJ` 的卡片（比较时忽略大小写与首尾空白）；图片初始 URL 必须使用 HTTPS，域名必须为 `loli.akkariin.moe` 或 `p.sda1.dev`。标签缺失、未知或其他评级一律跳过。

**LC0 是上游标注，不是插件的视觉审核结论。** 发现错误标注时应关闭推送并向来源反馈。图片下载和重定向由 NapCat 处理，初始 URL 白名单不能代替对上游图床的信任。请遵守来源规则和作者版权，不移除作品出处。

不要提交本地群配置、发送历史、运行日志、真实接口响应或消息截图。项目的测试通过模拟 HTTP 和 NapCat 完成，不向真实群发消息。

## 开发与验证

```sh
pnpm install
pnpm run typecheck
pnpm test
pnpm run build
pnpm run test:package
```

测试涵盖内容日边界、可发布标签过滤、公告行、消息格式、接口回退、缓存与并发、配置清洗、白名单、冷却、定时重试与停止、重启去重、实例重载和卸载等场景。真实发送效果应由使用者在自己的测试群验证，不将结果写入公开文档。

代码职责：

- `src/index.ts`：插件生命周期。
- `src/config.ts`：默认配置、校验与原生配置面板。
- `src/core/state.ts`：配置及成功记录持久化。
- `src/services/daily-service.ts`：接口请求、数据校验与消息组装。
- `src/services/api-service.ts`：定时任务、冷却与运行时管理。
- `src/handlers/message-handler.ts`：关键词匹配与 OneBot 发送。

插件使用 `src/napcat.ts` 描述所需的公共结构类型，不依赖 NapCat 内部实现或 SDK 运行时。上游新增图片域名时，需要审查并更新图片域名白名单。

## 故障排查

- **没有推送或关键词无响应**：检查总开关、对应功能开关、对应群白名单，以及机器人的入群和发言权限。
- **图片加载失败**：检查 NapCat 所在机器能否访问图片来源，并在本地查看发送错误日志。
- **接口请求失败**：检查运行机器到公共接口的网络连通性。插件不会读取浏览器 Cookie。
- **到时间仍无图片**：上游可能尚未更新；查看本地日志，等待下一轮重试。
- **当天不再重试**：连续失败已达上限，日志与群内提醒会给出最后失败原因；排查后重新保存配置或重载插件以恢复。

分享日志或提交问题前，请移除群号、账号、消息 ID、昵称、真实作品内容及其他可识别数据。
